# environment resolve to a combination nobody ever tested.

# ---- Retrieval: text towers, and one vision model behind a flag ----
# Images are embedded and captioned during ingest (scripts/promote_artifacts.py), so no vision model
# is loaded in a request — with one deliberate exception. A corpus ingested with
# `ingest_folder.py --skip-captions` carries `captions.deferred` in its provenance, and then
# `src/services/search/captions.py` loads Florence-2 to caption the frames a query is about to
# return (§6.1 option B, O(k) per query). That path exists for live-ingest demos, where 15 of the
# 18 ingest minutes are captioning. A normally-ingested corpus never loads it, and the transformers
# and timm pins below are inert weight for such a deployment — ~500 MB of model is only fetched
# on first use, never at import. Both were already present transitively via sentence-transformers;
# they are named here because a direct dependency belongs in the file that pins it. Florence-2 loads
# through the native `Florence2ForConditionalGeneration`, never `trust_remote_code` — the bundled
# remote code predates transformers v5 — which is also why no `einops` pin is needed.
#
# torch and torchvision MUST come from the same index and match. No `--extra-index-url` here: only
# linux/amd64 wants PyTorch's CPU index (its default PyPI wheel bundles CUDA, ~2.5 GB, for a
# service with no GPU). On linux/arm64 and Windows the default PyPI wheel is already CPU-only, and
# the CPU index does not reliably carry aarch64 builds — pinning it here would break the ARM build
# and local Windows installs to optimise one platform. The Dockerfile selects per TARGETARCH.
numpy==1.26.4
torch==2.13.0
torchvision==0.28.0
open_clip_torch==3.3.0
sentence-transformers==5.6.1
transformers==5.14.1
